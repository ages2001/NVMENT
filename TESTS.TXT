NVMENT 3.3 (2026-11-09)
===========================

Regression with the four release drivers of this round (2026-11-23)

- The QEMU changes these tests use (test hooks, the ICH5, Intel VMD and
  RST remapping models) are in tests/qemu/qemu-8.2.2-tests.patch
  (against the QEMU 8.2.2 source).
- NT 4.0 SP1: AHCINT (system disk and a data disk on ich9-ahci), IDENT
  (PIIX3 secondary), NVMENT, MMCSDNT (sdhci-pci) in one boot: four data
  volumes, each TAG.TXT read.
- NT 3.51 (MPS HAL, 2 CPUs, system disk on the ICH5 PATA model through
  IDENT, no PIIX IDE): the same four data disks, each TAG.TXT read.

  NVMe and SD: every byte equal.
- Windows 2000 SP4 and XP x64: see the Windows 7 section.

- Intel VMD on Windows 7 (second round): the VMD's start carried its
  MSI-X messages (33 descriptors), and ScsiPort failed the start with
  STATUS_INVALID_PARAMETER after HwFindAdapter (debug build, COM1 log).
  The Windows 7 HAL gives a vector through HalGetInterruptVector only
  for a line in use (PCI bus 9, 10, 11 ... but 0 for 5, 7, 13), and a
  line asked for in the resource requirements gave Code 12. This
  release leaves the messages out and lets the VMD share the ACPI SCI
  (level-triggered): HwFindAdapter, HwInitialize, Fast Polling, the VMD
  started (0180600A), TAG.TXT of the disk behind it read. With the
  release build installed by pnputil: the same. Windows 2000 SP4
  regression with this build: the VMD disk read (D:).
- The QEMU VMD model of the first round put its MSI-X capability on top
  of VMCAP/VMCONFIG (bus start read as 0 instead of 224); the capability
  is at 80h now (tests/qemu/qemu-8.2.2-tests.patch regenerated).

TRIM mode and trimnt (IDENT GitHub issue #2; 2026-11-09)

- QEMU 8.2, disks with discard=unmap on raw image files that were filled
  with random data before partitioning, so that every block of the image
  was allocated; one FAT16 partition each. Space given back by the
  emulated disk shows as a smaller allocation of the image file (du).
- Windows 2000 (w2k-hib, the four 1.3/1.8/3.3 release drivers): 200 MB
  disks on AHCI port 1 (AHCINT), the PIIX3 primary master (IDENT) and
  NVMe (NVMENT), a 256 MB SD card on sdhci-pci (MMCSDNT). trimnt D: to
  G: found each disk's adapter and address through
  IOCTL_SCSI_GET_ADDRESS ("D:\ is on Scsi0: path 0 target 1 lun 0",
  ...), switched TRIM mode on on that adapter only, filled 199 MB (SD:
  255 MB), "volume full", "trimmed 199 MB" (SD: 255 MB) from
  TRIM_STATUS. Image files: AHCI 204804 KB -> 3420 KB, IDE 204804 KB
  -> 8216 KB, NVMe 204800 KB -> 7416 KB. The SD image stayed allocated:
  QEMU 8.2's SD card model takes ERASE but neither changes nor discards
  the blocks. fsck.fat -n afterwards: no errors, no files left on any.

  10000 files of three sectors, every second one deleted (5000 holes of

  Number of Queues); QUERY_INFO after the runs: "queues 4 x 64 entries"
  on NT 3.51, NT 4.0, Windows 2000 and XP x64. The deepest queue
  reported (commands outstanding over all queues) reached 32 with
  bench.exe at queue depth 32 on NT 4.0 and XP x64; one queue holds 63.
  bench.exe on namespace 2 after trimnt on namespace 1 of the same
  controller (Windows 2000, XP x64): BENCH OK.

  longer touched): see TRIM above (every NVMe fill trimmed in full, the
  image files shrank to 6-7 MB).

SMART through the disk on XP x64 (added to 3.2, 2026-11-03)

- SMART through \\.\PhysicalDriveN (disk.sys) on XP x64: the request
  goes to the disk's PDO as IOCTL_SCSI_MINIPORT, which XP x64's ScsiPort
  (5.2.3790.1830) answers on a PDO with STATUS_INVALID_DEVICE_REQUEST
  (disassembly of its PDO device-control routine; only the adapter's
  device object takes it): smartt.exe reported ERROR_INVALID_FUNCTION on
  every disk of the driver, \\.\ScsiN: answered. The stock atapi.sys
  (not a ScsiPort miniport) answers on the same image. With the
  IRP_MJ_DEVICE_CONTROL front end the request is passed through the PDO
  as SRB_FUNCTION_IO_CONTROL (ScsiPort's PDO routine takes that function
  and fills in the disk's address).
- A first build without an MDL in that request stopped XP x64 with
  STOP D1 in ScsiPort (it maps the data of every request with
  DATA_IN/DATA_OUT through the IRP's MDL); with the MDL as below.
- XP x64 SP1 (5.2.3790.1830, ACPI HAL), an installed image moved to
  QEMU's PIIX3: system disk on the IDE primary master (IDENT), 256 MB
  disks as primary slave and secondary master, the XP x64 CD as
  secondary slave, a 256 MB disk on ICH9 AHCI port 1 (AHCINT), a 256 MB
  NVMe namespace (NVMENT); the three drivers installed with their INFs
  through SetupAPI. Release builds: bench.exe on the four data disks,

Host Memory Buffer, APST by default (added to 3.2, 2026-11-02)

QEMU 8.2's NVMe controller has neither; it was patched for these runs:
with QEMU_NVME_HMB=<KB> it reports HMPRE (that size) and HMMIN (half of
it) and takes Set Features 0Dh, checking every descriptor (page aligned,
the sizes adding up to HSIZE) by writing and reading back 16 bytes at
both ends of every piece; with QEMU_NVME_APST=1 it reports APSTA and two
non-operational power states (PS1: 1 ms entry / 2 ms exit, PS2: 5 ms /
